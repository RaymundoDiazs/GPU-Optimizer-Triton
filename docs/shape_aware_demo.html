Shape-Aware Kernel Filtering

A visual demo of our differentiator: tensor shapes guide candidate generation, then layered validation decides which kernels can be trusted.

Current evidence 27 generated candidates evaluated on a Tesla T4. 16 compiled, 16 matched PyTorch, and 16 produced speedup measurements.

Pipeline

1

PyTorch Task

The input starts as a PyTorch operation, such as Z = X + Y.

2

Shape Metadata

Tensor size, strides, and layout provide context before generating a kernel.

3

Shape-Aware Decision

The system chooses parameters such as BLOCK_SIZE, grid layout, and tiling strategy.

4

Candidate Kernel

The LLM output is treated as a candidate, not as the final answer.

5

Layered Filters

Grammar, GPU execution, PyTorch equivalence, and speedup checks decide if the kernel survives.

Shape-Aware Example

For vector addition, the tensor length controls how many Triton programs are launched. Poor choices can underuse the GPU or create unnecessary overhead.

Input N 1,048,576
Block size 256
Grid 4,096

grid = ceil(N / BLOCK_SIZE). The shape is not just input data; it becomes part of the kernel strategy.

What The Demo Shows

Shapes guide generation The shape influences block size, grid layout, and tiling decisions before the kernel is validated.
Filters protect correctness Valid-looking code is rejected if it fails Triton execution or PyTorch equivalence.
Speed matters last Performance is only meaningful after a kernel is functionally correct.
